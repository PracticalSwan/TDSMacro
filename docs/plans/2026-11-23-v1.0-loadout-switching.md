# v1.0 plan: verified loadout switching between strategies

**Status:** PLANNING ONLY. Authored 2026-11-23; baseline is released v0.5.1. No source implementation, live equip automation, saved-preset modification, or release is authorized by this plan alone.

**Goal:** On a user-configured strategy transition, return safely to the TDS lobby, select the next strategy's complete loadout (including perks and empty slots), verify it, then enter the next map/mode with exactly one guarded input controller. Support Golden Scout 10/9 and Hardcore Gem 3 / Gem+XP 4, with an extension point for future documented strategies. The live Golden Scout worker should remain untouched during planning.

## Existing constraints and reusable code

| Existing component | Current behavior | Proposed v1.0 seam |
| --- | --- | --- |
| `src/tds_auto/app.py` `STRATEGIES`, `Controller.start` | One manually chosen strategy per child worker | Add a **planned rotation selection** without changing existing single-strategy behavior |
| `src/tds_auto/session.py` preflight / menu / result loops | Golden verified inventory; Hardcore known towers; direct Play Again/Restart Match retains loadout | Extract **verified end-of-match-to-lobby boundary** so next leg starts from lobby |
| `src/tds_auto/navigation.py` `Navigator`, `TRANSITIONS` | Readable inventory search and exact result-to-lobby routes | Add bounded preset-selection UI states, positive-only confirmation |
| `src/tds_auto/loadout.py` | Exact searched names / UNEQUIP, Golden perk; auto-equip intentionally disabled because EMPTY slots not text-proven | Design **authoritative five-slot outcome verification** before enabling automatic changes |
| `src/tds_auto/control.py` `GuardedInput` | Foreground HWND/client/geometry, one guarded mouse/keyboard owner, F8/Escape | Reuse unchanged input guard; no second automation process |
| `src/tds_auto/observer.py`, `resources.py` | Pinned UI states and local OCR | Add separately calibrated and tested preset UI recognition |
| `src/tds_auto/recovery.py` | Up to 3 bounded client relaunches, preserves totals | Integrate only through one supervisor; never use recovery to bypass invalid loadout |

**Current code must not be assumed to auto-equip.** `Controller.start(auto_equip=True)` rejects it, and the in-session preflight rejects it. Historical `Session._equip_hardcore_tower` and `read_slot_occupancy` are *references*, not production-approved full loadout switching.

## Preferred switching method: saved TDS Loadouts presets

The actual 2026 inventory UI has a **Loadouts** button. Official 2026 release notes describe **four saved loadouts, or six with VIP**, but the native selection/readback behavior for this account has NOT yet been tested by the macro. External reference: https://tds.wiki/w/V1.89.0 .

### User one-time configuration

1. User saves a named **Golden Scout** preset: slot 1 Scout with active Golden perk, slots 2–5 empty.
2. User saves a named **Hardcore Gems** preset: Boomerang / regular Crook Boss / Farm / empty / empty.
3. For optional XP rotation, user may save a separate **Hardcore XP** preset: same first three plus a supported slot-4 XP tower (Juggernaut in the proven profile), slot 5 empty.
4. Preset names are convenience labels, **not proof of content**. The requirement documents remain the authority for the expected five-slot result.

### Proposed guarded switch transaction

1. After the final **verified** result of a leg, suppress the normal direct Play Again/Restart Match. Only a known verified Victory/Defeat result can authorize the corresponding existing **Return to Lobby** transition.
2. Require two stable observations of the **lobby**, verified Roblox foreground/window identity/1920x991/120-DPI, no overlay, no competing worker.
3. Open the actual inventory. Read the native Loadouts panel and find one **exact, unique** user-configured preset; never click a guessed icon/index.
4. Confirm the selected preset name and button **before click**, send **one** guarded selection, then confirm the game reports the expected new preset or changed inventory.
5. **Revalidate the complete ordered five-slot loadout** and Golden perk (if applicable) from authoritative text/UI evidence. Require exact slot numbers, required tower identities, empty slots and the absence of old towers. Do not treat a sparse thumbnail or border/portrait as proof of empty.
6. If the postcondition is unobservable or wrong, **stop at the verified lobby**, mark the switch incomplete, and ask for a manual correction. Never start the next match, never blindly select the preset again, never click Equip/Unequip based only on icon colors.
7. Only after full readback: enter the next strategy's existing verified map/mode/solo preflight and active strategy profile; retain all price/cash/camera/result guards. The switch is committed **before gameplay**, not based merely on the preset click.

### Alternatives and decision gates

- **Fallback (safe, initially useful):** manual loadout switching. When a preset cannot be safely selected/verified, stop rotation at the lobby, show the five required slots, and require explicit user continuation after the *existing read-only preflight* passes. This fallback does **not** satisfy a fully unattended 5+5 repeat loop.
- **Secondary future option:** verify individual Search -> exact card -> EQUIP/UNEQUIP with each target's unique text and a reliable **slot-index and explicit empty-slot readback** after each click. It is more fragile and slower than named presets and is not recommended as the primary path.
- **Hard blocker to automatic switching:** if current TDS exposes no trustworthy slot-index/EMPTY proof, automatic loadout switching must remain disabled. Never weaken the original Auto-Equip safeguard merely because a preset is available.
- A one-time switch between **Golden 9** and **Golden 10** may keep the same loadout, but **must change and verify the exact profile hash**. No inventory edits are needed only if a fresh read-only preflight proves the currently equipped loadout still matches.
- A swap **Hardcore 3 ↔ Hardcore XP 4** may change only slot 4; full five-slot readback is still required. XP tower base price is read in the next match, never trusted from preset metadata.

## Requirements and acceptance criteria (proposed v1.0)

- **L-01:** When a different strategy becomes next, the controller shall finish the current verified result and reach an independently verified lobby before touching equipment or starting the next match.
- **L-02:** The controller shall select only a uniquely identified user-saved preset and verify all five ordered slots and required perk against [strategy requirements](../requirements/strategies/README.md).
- **L-03:** If a slot/empty/perk/name is unreadable or a preset is missing, the controller shall stop safely **without starting another match**; it shall not infer the success of the switch from a selection click.
- **L-04:** On stop, pause, error, lost foreground, UI change, Roblox restart, or F8/Escape, no further inventory input may occur until a fresh explicit authorization/preflight.
- **L-05:** Presets shall never overwrite, delete, or rename user-managed loadouts. Only selecting an existing preset is planned for unattended operation.
- **L-06:** Existing single-strategy run, current release files, single-worker constraint, economy guards, existing manual equip policy and game recovery protections must remain unchanged until the v1.0 feature is proven.

## Native investigation and implementation tasks (future, NOT executed)

1. Record redacted UI states for Loadouts panel with 0/1/multiple saved presets, unique names, and VIP/non-VIP counts; inspect whether slot text/perk is actually readable.
2. Decide whether reliable full slot-order/empty verification is possible in the observed game UI. If **no**, implement manual switch gate only and mark unattended rotation blocked, not “completed.”
3. Add normalized strategy requirement registry (profile path/hash, required ordered loadout, mode/map, preflight) without changing existing executable profile files.
4. Add observer/navigation state transitions and **one-click** guarded preset selection, followed by an independent full postcondition.
5. Add in-match result-boundary-to-lobby transition and verified setup for the next strategy, retaining one input owner.
6. Add focused negative tests: wrong preset, duplicate names, changed UI, empty slots unreadable, non-Golden Scout perk, swapped Crook/Boomerang, unsupported XP tower, disconnected client, focus loss, delayed UI, click lost, pre/post click mismatch.
7. Prove a Golden → Hardcore → Golden switch **on native Roblox**, no overlapping workers, and no unintended changes to user-owned presets or prior strategies; then run multi-cycle trials with correct rewards. Only then enable it as an opt-in v1.0 feature.

## Releasing

This is a v1.0 feature design, **not a change to v0.5.1**. Interim corrective or incremental releases continue normally (v0.5.2, v0.6.0, v0.7.0, etc.) with their own regression/release gates. Do not pre-bump the current version, tag v1.0 or ship partial preset-selection as safe unattended automation.
