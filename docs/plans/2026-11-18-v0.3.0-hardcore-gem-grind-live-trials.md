### Acceptance series

- [ ] **3 agent-supervised complete 1× runs** with valid LIVE-00..LIVE-13 evidence, 3 confirmed gem payouts, zero unintended inputs. Supervision means Codex follows the macro's own native evidence and logs without clicking, focusing or controlling Roblox through a second tool; the user is not required to perform game input. Do not run two controllers.
- [ ] **10 consecutive unattended 1× gem cycles** with the same exact supported loadout, environment and one worker. Every cycle must have its own gem reward record and wall-clock duration. Preserve final success, loss and recovery ledgers. A defeat at the expected wave is success only when payout is confirmed.
- [ ] **Stop/recovery gates:** verify F2 during a cancellable interval; unknown-result stop; natural client focus loss fail closed; a detected game failure never duplicates previous purchase/sell. Existing v0.2.4 Error 278 success is historical, **not** a new v0.3.0 test. Error 277 remains an explicitly documented foreground limitation unless independently fixed and live-proven.
- [ ] **Golden Scout regression:** retain v0.2.4 source suite, exact strategy hash, 44-operation playback and prior release assets; do a proportionate guarded old-mode smoke/live trial if routing/calibration/input code changed materially.
- [ ] **Efficiency:** compute verified total gems, median and p95 cycle duration, median and p95 capture/OCR+action latency, skipped-wave failures, early-defeat rate, mean gems/hour, max consecutive success and storage bytes per cycle. Report actual ranges; never claim the owner's 3–7 minutes without measured cycles.

### Performance formula and example record schema

Gems/hour = 3600 × sum(credited_gems) / sum(full_cycle_wall_seconds).

A privacy-bounded per-cycle record should contain: strategy_id; profile_hash; mode/map; client geometry/DPI; wave_reached; result_status; credited_gems; wall_seconds; wave_skip_count; confirmed_place_count; confirmed_upgrade_count; confirmed_sell_count; tower_counts; speed_requested; speed_verified; ticket_consumed_if_any; OCR/action latency summaries; stop/recovery reasons; validation flags. Avoid account name, chat, screen image, purchase credentials or personal paths in public samples.

## What counts as blocked

A real blocker means an essential task cannot safely proceed because the game/account doesn't expose Hardcore or Wretched Front; required towers not equipped; native client geometry/foreground impossible; map/calibration evidence cannot be established; observed cost/limits make the strategy infeasible; a required result/credit cannot be read; or a guarded recovery cannot reach the foreground again. Report the exact evidence and earliest blocked gate, **do not** force input or invent completion. The user can then decide whether to change the written wave schedule, supported environment or release scope. Optional 1.5× and EXP failures are not blockers for an otherwise verified 1× release.
